# 최신 카메라별 hidden 비교와 라벨 재검수

2026-09-07. 기존 결과는 보존하고, 이후 확인한 결과·정정을 이 문서에 모았다.

## 먼저 결론

**전체 카메라 평균 + 작은 MLP를 기준선으로 유지한다.** 카메라별 특징을 이어 붙인 concat의
raw F1이 조금 높았지만 차이가 작고 불확실성이 커 더 복잡한 모델로 바꿀 근거가 부족했다.
이것은 저장된 특징의 단계 분류 실험이며, 실제 GR00T에 붙여 QA·성공 판정·pause를 검증한 결과는 아니다.

## 시연 50개: 카메라별 비교

대상은 `leapshared/Incline_new_20260902_203009`, 9,496시점이다.
원본 30 FPS에서 frame 0,6,12,…을 선택했다. 각 시점의 외부·양손목 이미지 3개를 함께 입력했다.
현재 GR00T 환경에서 전체 평균도 다시 추출해 같은 조건의 기준선으로 사용했다.

| 가져온 특징 | 차원 | Linear raw F1 | MLP raw F1 | MLP ordered F1 | MLP ordered 경계 MAE(초) |
|---|---:|---:|---:|---:|---:|
| 전체 카메라 평균 | 2048 | .8526 | .8853 | .8989 | 1.050 |
| 외부 카메라 토큰 | 2048 | .8540 | .8547 | .8819 | 1.187 |
| 왼쪽 손목 토큰 | 2048 | .8043 | .8071 | .8563 | 1.440 |
| 오른쪽 손목 토큰 | 2048 | .8404 | .8608 | .9010 | 1.002 |
| 양손목 평균 | 2048 | .8431 | .8818 | .9047 | 1.002 |
| 세 카메라 concat | 6144 | .8651 | .8902 | .9015 | 1.032 |

**raw**는 시점별 확률의 직접 예측, **ordered**는 전체 영상을 보고 5단계 순서를 강제한 오프라인 보정이다.
ordered가 높아도 실시간 경계 감지 성능이 좋다는 뜻은 아니다. F1은 accuracy와 다르다.

- 비교 조건: backbone 고정, LoRA off, action head 미사용. 카메라마다 88개 영상 토큰을 평균해 2048차원으로 만들었다.
- 분할: 32개 학습, 8개 early stopping 모델 선택, 10개 검증. 기존 seed42·episode split을 모든 조합에 공유했다.
- **검증 10개는 학습에는 없지만, 과거부터 여러 설계 비교에 사용했다. 손대지 않은 최종 test가 아니며 새 독립 test가 필요하다.**
- 학습: train-only scaler, Linear 또는 D→128→64→5 MLP, balanced loss, AdamW lr .001, batch256, 최대80 epoch, patience12, 단일 seed42.
- 같은 3-camera forward의 토큰 위치만 나눈 실험이다. 다른 카메라 입력을 제거한 camera-only ablation이 아니므로 ‘손목 영상 추가의 순수 효과’로 해석하지 않는다.
- 과거 특징은 FPS 필터·backbone 코드 조건이 달라 과거 .9020과 이번 .8989의 차이를 카메라 효과로 계산하지 않는다.

concat MLP는 전체 평균보다 raw F1이 .00493 높지만 사전 최소 개선 기준 .01에 못 미쳤다.
파라미터는 270,853→795,141로 약 2.94배다. 검증 episode별 F1 차이 평균의 paired bootstrap
95% 구간은 [-.0097,+.0191]로 0을 포함한다. 이 구간은 단일 training seed와 10개 episode의 보조 분석이며
여러 후보를 비교한 선택 편향을 해결하지 않는다.

원본 [12조건 CSV](../archive/camera_review_20260907/demo_results.csv)와
[split·학습 조건·bootstrap JSON](../archive/camera_review_20260907/demo_summary.json)을 함께 보존했다.
GPU 추출은 1,010.65초, backbone 평균 74.09ms/시점(batch4), peak allocated VRAM 6,536.55MiB였다.
모델 로드·최종 archive 저장·전송은 총 시간에 포함하지 않으며, backbone 지연은 전처리·pooling·action을 제외한다.
실시간 추가 지연·host RAM delta는 이번에 측정하지 않았다.

## rollout 참조 라벨 정정

대상은 `leapshared/rollout_Incline_20260903_20260903_190043`의 109.7초 episode 000이다.
손목 영상·action을 다시 보니 기존 4개 경계가 실제 release보다 늦었다.
예를 들어 49초에는 첫 추가 이미 카트에 있지만 기존 라벨은 아직 0개였다.
**기존 라벨이 ‘첫 gripper opening frame’이라는 설명은 영상과 맞지 않는다.**

| 경계 | 기존 참조(초) | 검수용 후보(초) | 시각적 후보 구간(초) |
|---|---:|---:|---|
| 첫 추 | 51.100 | 46.000 | 45.5–46.5 |
| 둘째 추 | 65.333 | 56.167 | 56–57 |
| 셋째 추 | 94.700 | 86.900 | 86–88 |
| 넷째 추 | 102.867 | 100.133 | 100–101.5 |

후보는 영상으로 성공 시도 구간을 고른 뒤, action index15의 전후 중앙값 감소가 가장 큰 지점으로 잡았다.
release 전환의 proxy이지 물체가 안정적으로 적재된 첫 frame의 확정값은 아니다.
88초의 사람 손 개입과 안정적 적재 유지시간·가림 처리도 추가 검수가 필요하다.
[후보 JSON의 근거·계산 창·주의사항](../archive/camera_review_20260907/rollout_candidate_labels.json)을 확인한다.

원본 fixture·기존 점수·기존 디버그 영상은 변경하지 않았다. 영상의 일부 ‘예측 ≠ 참조’는
분류기 오류가 아닌 참조 오류일 수 있다. 기존 ‘첫 성공을 5.9초 빨리 예측’이나 MAE2.783초를
실제 성공 판정 성능으로 사용하는 것은 재검수 전까지 보류한다.

후보 라벨로 같은 영상 OOF를 다시 비교한 결과(각 칸 native / PCA256 raw F1):

| 특징 | 후보 라벨 raw F1 |
|---|---:|
| 전체 평균 | .641 / .634 |
| 외부 | .675 / .683 |
| 왼쪽 손목 | .700 / .690 |
| 오른쪽 손목 | .544 / .545 |
| 양손목 평균 | .624 / .615 |
| concat | .649 / .685 |

[기존 라벨 CSV](../archive/camera_review_20260907/rollout_original_results.csv)와
[후보 라벨 CSV](../archive/camera_review_20260907/rollout_candidate_results.csv)는 구분해 보존한다.
라벨 변경에 따라 OOF 분할도 달라지므로 두 표 사이 차이를 카메라 효과로 계산하지 않는다.
후보 라벨도 임시이며, 같은 영상의 다른 구간을 학습한 결과다. 시연50개 분류기의 무학습 전이 성능은 아니다.
